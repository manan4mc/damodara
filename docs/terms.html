How backups work

Damodara creates backups while your Minecraft server is running. It makes a live copy of your files without pausing the server. This is best-effort. Files that change during the copy may not all be captured at exactly the same moment, so a backup can be inconsistent.

Because Damodara runs inside the server, scheduled backups can only happen while the server is running.

Schedules and catch-up

Scheduled backups follow the settings your administrator sets in config.yml. If the server is off when a backup is due, Damodara can't make that backup. If catch-up is enabled, it can make one fresh backup after the server starts. It does not recreate the backup that was missed.

Where backups are stored

Backups can be saved to the local folder you configure and uploaded to the server owner's Google Drive account. Uploading to Google Drive only works after the owner authorizes Damodara to access their account.

Retention

Local retention and Google Drive retention are separate settings.

  • Local: Older local backup archives may be deleted based on the limits you configure.
  • Google Drive: Retention is off by default. If an administrator turns it on, Damodara moves eligible older Damodara backups to your Google Drive Trash. It does not permanently delete them. Google's own Trash rules apply from there.

Choose these settings carefully so you keep as many backups as you need.

Restoring

Restoring a running server in place is not supported. Restore backups only with the Minecraft server stopped. Test your restore process before you need it.
